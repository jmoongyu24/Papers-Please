**nDCG 는 이 표에 없다.** `grades_test.jsonl` 을 넓히지 않아서 판정 없는 논문이 0점으로
세어진다. 고정한 평가 규칙에 따라 넓히지 않았다 ([../evaluation/README.md](../evaluation/README.md)).

### 짝지어 검정 (시험용 342문항, 부트스트랩)

기준선 `test_arxiv_only_raw` 대비 Recall@10:

| 구성 | 차이 | 95% 신뢰구간 | p | 판정 |
|---|---|---|---|---|
| 파인튜닝 전 | +0.427 | [+0.374, +0.480] | <0.001 | 유의미 |
| 파인튜닝 후 | +0.439 | [+0.386, +0.491] | <0.001 | 유의미 |
| 파인튜닝 후 + 순위 합치기 | +0.468 | [+0.415, +0.520] | <0.001 | 유의미 |

파인튜닝 전 `test_multiquery_d100` 대비 Recall@10:

| 구성 | 차이 | 95% 신뢰구간 | p | 판정 |
|---|---|---|---|---|
| 파인튜닝 후 | +0.012 | [-0.032, +0.056] | 0.632 | 판정 불가 |
| 파인튜닝 후 + 순위 합치기 | +0.041 | [-0.003, +0.085] | 0.085 | 판정 불가 |

**색인 파인튜닝만으로는 시험용 342문항에서 개선을 입증하지 못했다.** 순위 합치기를 함께
켜도 p=0.085 로 채택 기준 p<0.05 에 미달한다. 보고서에 "파인튜닝이 성능을 올렸다" 고
적으면 안 된다. 채택 근거는 위 '지금 서비스와 옛 서비스' 절에 적은 두 가지다.

> 위 표의 실행 이름은 파일 이름으로 적었다. `evaluation.report` 가 찍는 이름은 결과 파일
> `_meta` 의 `rewriter` 값이라 `test_multiquery_d100` 이 `translate` 로, `test_ft_v2` 가
> `passthrough` 로 나온다. 파일 이름으로 읽을 것.

## 다시 계산하기 (검색 0회)

```bash
python -m evaluation.report --run results/test_arxiv_only_raw.jsonl \
    results/test_ft_fused.jsonl --queries data/eval/test.jsonl
```

## 파일을 넣을 때 함께 적을 것

1. **어느 평가셋에서 잰 값인가** (`dev.jsonl` / `test.jsonl`)
2. **어느 커밋인가** (결과 파일의 `_meta` 줄에 자동으로 들어간다)
3. **기준선 값이 함께 있는가** — 없으면 "좋아졌다" 를 말할 수 없다

> **`test_multiquery_d100.jsonl` 의 `_meta` 줄은 실제 실행과 다르다.**
> `rewriter: translate`, `channels: [local_dense]`, `rerank: none` 으로 적혀 있으나
> 파일 안에는 검색어 2개와 채널 2개와 재정렬 결과가 들어 있다. `--report-only` 에
> `--out` 을 주면 결과 줄만 새로 쓰고 실행 정보 줄은 옛것을 보존하기 때문이다.
> **성능 값은 맞고 `_meta` 의 실행 정보만 틀리다.**
