## 1. 푸는 문제

논문을 찾는 사람은 **자기가 읽고 싶은 논문이 어떤 검색어로 쓰여 있는지 모름.**

- 그 분야를 모르는 사람은 일상어로 검색함. "사진 보고 글로 설명해주는 인공지능"
- 어느 정도 아는 사람도 논문이 실제로 쓰는 용어를 못 맞힘. "이미지 설명 생성 모델"이라고
  치지만 논문은 `image captioning`, `vision-language model` 이라고 씀.

한국어로 물으면 arXiv 는 아예 못 찾음. 한국어 질문을 그대로 넣으면 88.2%가 결과 0건임
(arXiv 가 한글을 색인하지 않음).

### 이번 단계에서 만드는 것

> 사용자가 입력한 검색어로 실제로 존재하는 논문의 제목과 초록을 찾아 보여줌.

찾은 논문을 언어 모델이 요약해 답변을 만드는 기능은 범위 밖임. 다만 각 논문이 왜 질문에
맞는지 이유를 붙이는 것까지는 만들었음.

### 지켜야 할 조건

| 조건 | 뜻 |
|---|---|
| 로컬 실행 | 서비스가 돌 때 유료 인공지능 서비스에 의존하지 않음 |
| 배포 가능 | 다른 사람이 명령어 한 줄로 설치·실행할 수 있어야 함 |
| 오픈소스 | GitHub 공개 + 자유 라이선스 |

유료 서비스(OpenAI)는 **평가용 데이터를 미리 만들 때만** 씀. 서비스가 돌 때는 쓰지 않음.

## 2. 실측이 바꾼 방향 (정직하게 기록)

처음 가설은 "입력한 말 → 의도 → 개념 → 전문 용어 순서로 단계적으로 변환하면 단계마다 검색이
좋아짐" 이었음. **세 번 검증해 세 번 다 반증됐음.**

| 무엇이 성능을 만들었나 | 검증 |
|---|---|
| **논문 71만 편 로컬 의미 검색** | 옛 평가셋에서 +0.243, p<0.0001. 지금 성능의 대부분임 |
| **교차 인코더 재정렬** | 옛 평가셋에서 0.343 → 0.427, p<0.001 |
| **한국어를 영어로 옮겨 넣기** | 시험용에서 한국어 Recall +0.111, p=0.001. 학습 0회 |
| ~~계층 변환~~ | 반증됨 |
| ~~검색 성공 보상 학습(SFT/DPO)~~ | 지금 구조에서 기여 판정 불가(p=0.101), 만족도는 나빠짐 |

### 왜 학습한 변환기가 지금은 기여하지 않는가

변환기가 만든 검색어는 **arXiv 채널로만 들어감.** 로컬 의미 검색은 원본 질문(한국어면 번역문)을
씀. 그런데 arXiv 채널이 후보 확보에 보태는 몫은 시험용 기준 0.038 뿐임. 즉 변환기를 아무리
잘 만들어도 지금 구조에서는 0.038 이 천장임.

**주장이 틀린 것이 아니라 조건이 바뀐 것임.** arXiv 키워드 검색이 유일한 통로였을 때는
변환기가 한국어를 건너게 해 주는 유일한 수단이었고(0.013 → 0.333, 25배), 로컬 의미 검색이
그 역할을 더 잘하게 됐음. **변환 결과를 어느 채널에 넣느냐가 전부였음** — 같은 변환이라도
로컬 채널에 넣은 번역은 크게 이득이었음.

### 지금 시스템의 가치 축

| 축 | 내용 | 상태 |
|---|---|---|
| (A) 언어 다리 | arXiv 가 검색할 수 없는 한국어 질문을 영어로 옮겨 찾게 함 | 확정 |
| (B) 뜻으로 찾기 | 글자가 안 맞아도 뜻이 맞으면 찾음. 로컬 71만 편 + 재정렬 | 확정 |
| (C) 과정 보여주기 | 무엇을 어떻게 알아들었는지 화면에 보여 줌 | 성능 향상 수단이 아니라 설명 기능임. 이 점을 감추지 않음 |

## 3. 시스템 구조

```
사용자 질문 (한국어 또는 영어, 일상어 또는 전문어)
   |
   +- [특정 논문을 지목하는 질문인가?] paper_resolver 가 따로 처리
   |
   +- 한국어면 영어로 옮김 (번역 변환기)
   |
   +- 채널 B : 로컬 의미 검색 71만 편        <- 정확도 담당
   +- 채널 A : arXiv 실시간 키워드 검색      <- 최신성·범위 담당
          |
     후보 합치기
          |
     교차 인코더 재정렬 (원본 질문과 대조)

     추천 이유 생성

     화면에 10편
```

## 4. 논문 모음

### 로컬 색인 — 716,183편

- Kaggle arXiv 스냅샷에서 컴퓨터·통계학습·전기전자 계열 + 2021년 이후 논문을 전부 추출함.
  `data/corpus/corpus-cs2021.jsonl` 1.03GB, 임베딩 2.93GB.
- **표본이 아니라 조건에 맞는 논문 전체임.** 표본 추출 방식에 따른 왜곡이 없음.

### arXiv 실시간 검색

로컬 색인은 만든 시점 이후 논문을 모름. 그 부분을 실시간 검색이 담당함.
**역할은 정확도가 아니라 최신성과 범위임.**

- 요청당 3초 간격, 단일 연결을 지켜야 함. 안 지키면 429/503 이 남(#12).
- 바깥을 부르는 곳에는 시간 제한을 걸어야 함. 안 걸면 응답이 안 와도 영원히 기다림(#38).
- 한글을 색인하지 않음.

### arXiv 정책

- 메타데이터(제목·초록·번호)는 CC0 라 저장·재사용 가능. **논문 원문은 우리가 제공하면 안 됨.**
- 출처 표기와 "arXiv 의 후원·보증을 받지 않았다"는 문구가 화면에 있어야 함. **적용 완료.**

## 5. 성능을 어떻게 재는가

1. **기준선을 반드시 함께 잼.** 핵심 주장이 "이렇게 하면 좋아진다"이므로 아무것도 하지 않은
   값이 없으면 주장이 검증되지 않음.
2. **지표 두 개를 나란히 봄.** Recall@10(질문을 만든 그 논문 1편을 찾았나)과
   nDCG@10(상위 10편이 얼마나 쓸모 있나). 두 값이 갈리면 그것은 지표의 성격 차이임.
3. **짝지은 부트스트랩 검정을 붙임.** p 가 0.05 보다 크면 "차이가 없다"가 아니라
   **"있는지 없는지 모른다"** 임. 모르는 차이로 설정을 고르면 시험지만 소모됨(#25).
4. **개발용과 시험용을 섞지 않음.** 탐색은 `data/eval/dev.jsonl` 에서만, 확정 판정만
   `data/eval/test.jsonl` 에서 함.
5. **서비스와 같은 조건으로 잼.** 평가 경로와 서비스 경로가 다르면 잰 값이 무의미함
   (로컬 평가 0.74 대 실제 서비스 0.15 를 겪은 적 있음 — #10).

## 6. 남은 계획

우선순위와 근거는 [PROGRESS.md](PROGRESS.md) 4절에 자세히 있음. 요약하면 다음과 같음.

1. **서비스 구성 확정 + 그 구성으로 재측정** — 지금 보고할 수 있는 서비스 성능 숫자가 없음.
2. **후보 깊이 실험** — 깊이 100 에서 300 으로 늘리면 후보 상한이 0.635 에서 0.721 로 오름.
   실제 이득과 응답 시간을 같이 잼.
3. **hard 층(일상어) 대책** — 실패 원인이 후보 확보 실패로 특정됐음. 일상어 질문을 학술
   문장으로 다시 쓴 뒤 **로컬 채널에** 넣는 실험부터 함.
4. **서비스 마무리** — 응답 시간, 배포, 라이선스, 피드백 적재.

### 하지 않기로 한 것

| 항목 | 이유 |
|---|---|
| Elasticsearch 색인 | 로컬 의미 색인 + arXiv 실시간으로 충분 |
| 어휘 조회, 상용구 필터 | 정답 논문 초록을 베끼는 편향이었음(#22). 코드 삭제 |
| 검색어 용어 손질 | 모든 K 에서 성능이 떨어졌음(#33). 코드 삭제 |
| 정답 논문에서 라벨 뽑아 재학습 | 처음 보는 논문의 고유 용어는 질문만 보고 유추 불가(#17) |
| 후보 깊이 1000 | 재정렬 비용이 후보 수에 비례함. 먼저 300 에서 이득을 확인함 |
| 답변 생성 요약 | 이번 범위 밖 |

## 부록. 용어

| 말 | 뜻 |
|---|---|
| 코퍼스 | 검색 대상 논문 모음 |
| 임베딩 | 글을 뜻이 담긴 숫자 배열로 바꾼 것. 뜻이 비슷하면 숫자도 비슷해짐 |
| 의미 검색 | 임베딩끼리 견줘 뜻으로 찾는 검색. 글자가 달라도 찾음 |
| 단어 일치 검색 | 같은 낱말이 나오는지로 찾는 검색. arXiv 키워드 검색이 이쪽임 |
| 순위 합치기(RRF) | 여러 검색 결과를 점수가 아니라 등수로 합치는 방법 |
| 재정렬 | 넓게 가져온 후보를 다시 줄 세우는 단계 |
| 교차 인코더 | 질문과 논문을 함께 읽어 관련도를 매기는 모델. 느리지만 정확함 |
| LoRA | 큰 모델은 얼려 두고 작은 보조 행렬만 학습하는 방법 |
| SFT | 지도 미세조정. 정답 예시를 보여 주는 학습 |
| DPO | 선호 학습. 둘 중 어느 쪽이 나은지를 쌍으로 보여 주는 학습 |
| Recall@K | 상위 K편 안에 정답이 들어온 비율 |
| nDCG@K | 상위 K편이 얼마나 쓸모 있는가. 등급 정답지가 있어야 잼 |
| 후보 상한 | 후보 안에 정답이 들어 있는 비율. 재정렬로 이 값을 넘을 수 없음 |
| 부트스트랩 | 표본을 다시 뽑기를 반복해 차이가 우연인지 재는 방법 |
