## 1. 단계별 성능 — 무엇이 성능을 만들었는가

**개발용 348문항 · Recall@10.** 단계마다 하나씩만 더했음. 저장된 검색 결과로 계산해
추가 비용 0원. 기준선 색인은 `cs2021`(원본 `BAAI/bge-m3`).

### 읽는 법

**성능의 대부분은 두 가지에서 나옴.** arXiv 키워드 검색을 로컬 의미 검색으로 바꾼 것
(+0.144)과 교차 인코더 재정렬(+0.118). 둘이 전체 상승분 +0.549 의 절반임.

**쿼리 변환의 +0.198 은 arXiv 검색 문법을 만들어 준 효과임.** 원본 한국어 질문을 arXiv 에
그대로 넣으면 한국어 Recall 이 **0.017** 로 거의 아무것도 못 찾음. 로컬 색인으로 옮기고
나면 변환의 몫은 +0.040(번역)으로 줄어듦. **arXiv 검색에서만 필요한 기능임.**

**한국어와 영어의 격차가 닫힘.**

```
①  한국어 0.017  영어 0.155   차이 0.138
④  한국어 0.448  영어 0.489   차이 0.041   <- 번역을 넣은 자리
⑥  한국어 0.575  영어 0.575   차이 0.000
⑧  한국어 0.632  영어 0.638   차이 0.006
```

**hard 난이도는 여전히 미해결.** ⑧에서도 0.310 임 — 일상어로 물으면 10문항 중 7문항은
그 논문을 못 찾음. 다만 이 층은 두 숫자를 함께 봐야 함: 시험용에서 hard 의 **88.6%** 는
상위 10편에 등급 2 이상인 쓸모 있는 논문을 한 편 이상 보여줬음.

**가상 초록(⑤)은 색인에 따라 효과가 갈림.** 이 표(원본 색인)에서는 −0.011 로 손해이고,
미세조정 색인에서는 +0.037 임. 미세조정 색인에서 이득은 한국어(+0.075, p=0.007)와
medium(+0.095, p=0.007)에 있고 hard 는 −0.026 임. 자세한 것은 PROGRESS 문제 1 참고.

## 3. 재정렬기 미세조정 — 세 번의 실패 기록

이 프로젝트에서 가장 많은 시간을 쓰고 성과가 없었던 부분임. 보고서에 그대로 실을 것.

**왜 시도했는가.** hard 난이도에서 정답이 후보 100편 안에 있는데도 상위 10편에 못 드는
문항이 24개였고, 그 문항들의 정답 점수 중앙값이 **0.0035**, 10등이 **0.0152** 였음.
정답을 오답보다 낮게 매긴 것이 아니라 후보 100편 **전부**에 '관련 없음' 에 해당하는 값을
줬음. 순서 문제가 아니라 점수를 만드는 능력의 문제였음.

| 시도 | 바꾼 것 | 결과 |
|---|---|---|
| 2026-08-17 | 모델 교체 (`bge-reranker-v2-gemma`) | 상위 10편의 36.7% 에 같은 최대값. hard 회수율 0.558 그대로 |
| 2026-08-27 | 우리 자료로 미세조정 | 상위10 서로 다른 값 2,304 → **607**. 점수가 1 에 몰림 |
| 2026-08-28 | 학습 자료의 결함을 고쳐 재학습 | 점수 뭉침은 풀렸으나 무관 논문 구별을 잃고 Recall 0.618 → 0.592 |

### 2026-08-28 시도의 자세한 값

학습 자료에서 **문항의 64.5% 에 어려운 오답이 하나도 없었음**을 실측으로 발견해 고쳤음
(오답을 "정답보다 재정렬 점수가 높은 논문" 에서 "정답을 뺀 검색 상위 4편" 으로).

| | 통과선 | 원래 모델 | 1차 실패본 | 2차본 |
|---|---|---|---|---|
| 무작위 논문 점수 중앙값 | 0.001 미만 | 0.00006 | 0.00172 | **0.00044 통과** |
| 무작위 논문 0.002 이상 | 0.10 미만 | 0.030 | 0.477 | **0.348 불합격** |
| 상위10 서로 다른 값 | 1,500 이상 | 2,304 | 607 | **1,528 통과** |
| hard 1등−10등 차이 | 0.05 이상 | 0.1168 | 0.0249 | **0.1655 통과** |

| Recall@10 (개발용) | 원래 재정렬기 | 2차본 | 차이 | p |
|---|---|---|---|---|
| 전체 | **0.618** | 0.592 | −0.026 | 0.121 |
| medium | **0.672** | 0.612 | −0.060 | 0.057 |
| hard | 0.267 | 0.250 | −0.017 | 0.694 |

### 왜 세 번 다 실패했는가 (소스로 확인)

두 손실 함수 모두 **점수 전체에 같은 상수를 더해도 손실값이 변하지 않음.**

```
CachedMultipleNegativesRankingLoss   cross_entropy_loss(logits, labels=0)      소프트맥스
RankNetLoss (LambdaLoss 상속)         sigmoid(sigma * (logits[i] - logits[j]))  차이만 씀
```

즉 **점수의 절대값을 붙잡는 항이 없음.** 순서는 가르칠 수 있어도 "무관한 것은 0 에 가깝게"
는 못 가르침. `LoRA` 가 `classifier.dense`(점수를 내는 머리)까지 학습하는 것도 그 길을
열어 둠. 절대값을 붙잡으려면 `BinaryCrossEntropyLoss` 같은 손실이 필요한데, 그러면 오답의
상당수가 실제로 쓸모 있는 논문이라는 문제가 되돌아옴.

**얻은 것:** 재정렬기를 건드리지 않고 **재정렬 순위와 검색 순위를 합치는 것**이 같은 목표를
더 싸게 달성함. 학습 0시간, 개발용 +0.060 (p=0.003) · hard +0.129 (p=0.001).

## 4. 서비스에 채택한 구성

**미세조정 색인(`cs2021-ft`) + 원래 재정렬기 + 순위 합치기 3:1**

```
질문 → 한국어면 영어로 옮김 (검색어 1)
     → 질문에 답할 법한 영어 초록을 지어냄 (검색어 2)
     → 각각 로컬 색인 71만 편에서 100편 (합집합 평균 186편)
     → 순위 합치기(RRF)로 상위 100편
     → 교차 인코더가 (원본 질문, 제목+초록) 을 읽고 점수를 매김
     → 재정렬 순위와 검색 순위를 3 대 1 로 다시 합침
     → 상위 10편
```

| 개발용 348문항 | 전체 | easy | medium | hard | 한국어 | 영어 |
|---|---|---|---|---|---|---|
| 기준선 (지금 서비스) | 0.575 | 0.914 | 0.629 | 0.181 | 0.575 | 0.575 |
| **채택 구성** | **0.635** | 0.914 | 0.681 | **0.310** | 0.632 | 0.638 |
| 차이 | **+0.060** | +0.000 | +0.052 | **+0.129** | +0.057 | +0.063 |
| p | **0.003** | 1.000 | 0.281 | **0.001** | 0.052 | 0.032 |

**주 지표(전체 Recall@10)가 고정한 채택 기준 p < 0.05 에 미달했음(p=0.085).**
규칙대로면 "있는지 없는지 모름" 이고 채택하지 않음.

**함께 적어야 할 사실들.**

- **개발용에서 잰 값이 시험용에서 방향과 크기 모두 재현됐음** — 개발용 +0.060(p=0.003),
  시험용 +0.041. 신뢰구간이 [−0.003, +0.085] 로 0 을 아슬아슬하게 걸침.
  **"효과가 없다" 가 아니라 "342문항으로는 이 크기를 잡아낼 힘이 모자라다" 임**
- **여섯 무리 중 다섯에서 방향이 양수이고, 유의미하게 나빠진 무리가 하나도 없음**
- **한국어에서 유의미함**(+0.070, p=0.045). 이 프로젝트의 확정된 가치 축임
- 문항 단위로 38개를 새로 맞히고 24개를 잃음

**후보 상한과 회수율 (시험용, 전체)**

```

재정렬이 실제로 본 후보 100편        0.754
최종 Recall@10                   0.658    (상한의 87.2% 회수)
```

hard 층은 후보 상한 0.500 에 최종 0.333 임. 재정렬이 상한의 66.6% 를 회수함.

## 5. 값을 인용할 때 지킬 것

1. **개발용과 시험용을 섞지 말 것.** 개발용은 탐색용이라 여러 번 봤고, 시험용은
   확정 판정에만 씀(ISSUE #25).
2. **p 값이 0.05 보다 크면 "차이가 없다" 가 아니라 "있는지 없는지 모른다".**
3. **nDCG 절대값은 등급 정답지가 넓어지면 내려감.** 판정 편수가 늘면 IDCG 가 커짐.
   2026-08-18 확장 전후 값을 섞어 비교하면 안 됨.
4. **후보 상한과 최종 Recall 을 구별할 것.** 상한은 재정렬 전 후보 안에 정답이 있는
   비율이고, 재정렬로 그 값을 넘을 수 없음.
5. **hard 층은 Recall 과 '쓸모 있는 논문 한 편 이상' 을 함께 볼 것.** Recall 0.310 이지만
   88.6% 의 질문에는 등급 2 이상인 논문을 보여줌.
