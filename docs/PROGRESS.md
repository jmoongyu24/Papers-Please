## 로그

- **2026-07-28(3)** — **arXiv HTTPError 원인 규명·해결 → 오류 0건으로 최종 성능 확정**.
  오류 정체는 **HTTP 429(요청 과다) 4건 + 503(서버 과부하) 3건**으로, 쿼리 내용과 무관한 순수
  속도 문제였음. 기존 백오프(5→10초, 총 15초)가 너무 짧아 arXiv 회복 전에 시도를 소진한 것이 원인.
  → 시도 3→5회, 대기 15→30→60→120초, **429/503은 대기 2배**, 무작위 지연 추가(#12).
  검증: 실패했던 7개 쿼리 재시도 **7/7 성공**(27초). 이후 40문항 재평가에서 **오류 0건**.
  **최종 성능(40문항)**: 학습 전 0.150 → SFT 0.300 → **SFT+DPO 0.350**(p=0.004, 2.33배).
  DPO 단독 추가 이득(+0.050)은 표본 40문항에서 불확실(p=0.444).
- **2026-07-28(2)** — **확보율 개선 시도 실패 + DPO 선호 학습(추가 이득 미확인)**.
  확보율 28%를 프롬프트로 올리려 두 가지 시도 → 모두 실패(형태 다양화: 실패 질문 전부 미검색 /
  표현 다양화: 용어 동일 + 사고 과정 유출 부작용). **병목은 프롬프트가 아니라 모델의 어휘 자체**임을
  재확인. DPO는 선호쌍 99개로 학습해 선호 정확도 93.75%·과적합 없음이었으나, **검색 성능에서는
  SFT 대비 +0.030(p=0.759)로 유의미하지 않음**. 세 모델 공정 비교(33문항): 학습 전 0.182 →
  SFT 0.364 → SFT+DPO 0.394. 향상의 대부분은 SFT에서 나옴. 평가 중 arXiv HTTPError 7건(17.5%)
  발생해 공정 비교를 위해 공통 성공 문항으로 재계산. `training/train_dpo.py`.
- **2026-07-28** — **쿼리 변환기 미세조정 완료 → 검색 성능 2배 향상(통계적으로 유의미)**.
  학습 데이터 **SFT 84개**(질문 300개 처리, 확보율 28%) 확보. 후보 형태 다양화(AND·제목 검색)는
  A/B 테스트에서 **효과 없음**으로 확인돼 미채택 — 문제는 쿼리 형태가 아니라 **용어 자체**임이
  입증됨. 16GB VRAM에 bf16이 9.7GB로 들어가므로 **4비트 양자화 없이** 학습(LoRA r=32, 8에폭).
  **과적합 발견**(검증 손실 에폭3 최저 0.513 → 에폭8 0.725) → **checkpoint-54(에폭3)** 채택.

  한국어 0.10 → **0.35**, hard 0.385 → 0.615. 개선 7문항/악화 1문항. 실제 변화 예시:
  "약물 개발" → `drug development`(미검색)에서 `drug discovery`(1등)로 어휘 교정.
