# 진행 상황 (PROGRESS)

이 문서 하나만 읽으면 프로젝트 전체를 알 수 있도록 만든 요약본이다.
문제 기록은 [ISSUE.md](ISSUE.md), 계획은 [PLAN.md](PLAN.md), 모듈 상세는
[MODULE_SPECIFICATION.md](MODULE_SPECIFICATION.md), 평가 사용법은
[../evaluation/README.md](../evaluation/README.md) 에 있다.

- 마지막 갱신: **2026-08-14 (저녁, 새 평가셋 기준선 측정 완료)**
- 이 프로젝트가 만드는 것: 한국어나 일상어로 물어봐도 arXiv 에서 원하는 논문을 찾아주는 검색 서비스

이 문서에서 쓰는 말:

| 말 | 뜻 |
|---|---|
| Recall@10 | 검색 결과 상위 10편 안에 찾던 논문이 들어온 비율. 0.45 이면 100번 중 45번 성공 |
| Recall@1 | 검색 결과 1등이 바로 찾던 논문인 비율 |
| nDCG@10 | 상위 10편이 얼마나 만족스러운가. 정답 1편이 아니라 **여러 논문의 등급**으로 잰다 |
| 후보 상한 | 후보를 다 모았을 때 그 안에 정답이 들어 있는 비율. 재정렬로도 이 값을 넘을 수 없다 |
| 교차 인코더 재정렬 | 질문과 논문을 함께 읽어 관련도를 다시 매겨 순서를 바꾸는 단계 |
| 확정 / 미확정 | 검증을 거쳤는가 아닌가 |

## 1. 지금 상태 한 장 요약

### 새 평가셋(v2) 기준선 — 2026-08-14 확정 (시험용 342문항)

| 구성 | Recall@10 | nDCG@10 (만족도) |
|---|---|---|
| **한국어를 영어로 옮겨 로컬 검색** ← **지금 가장 좋음** | **0.608** | **0.512** |
| 변환기 있음 (dpo) + 두 채널 = 옛 서비스 구성 | 0.570 | 0.442 |
| 로컬 의미 검색 단독 (번역 없음) | 0.553 | 0.484 |
| 변환기 없음 + 두 채널 | 0.553 | 0.458 |
| arXiv 단독 | 0.389 | 0.251 |
| 후보 상한 (재정렬이 실제로 본 것) | 0.681 | 회수율 83.7% |

목표는 Recall@10 **0.70**. 지금 0.608 이고 후보 상한이 0.681 이므로, **후보를 더 확보하지
않는 한 남은 여지는 0.073 뿐이다.**

### 한국어를 영어로 옮기는 것이 오늘 가장 큰 개선이었다

arXiv 논문은 제목도 초록도 영어다. 로컬 색인이 다국어 임베딩(bge-m3)을 쓰는데도 한국어
질문이 크게 뒤졌고, **번역만 해서 넣으니 격차의 절반 이상이 메워졌다.**

| 시험용 342문항 | 원본 | 번역 | 차이 |
|---|---|---|---|
| 한국어 Recall@10 | 0.456 | **0.567** | **+0.111 (p=0.001)** |
| 한국어 nDCG@10 | 0.400 | **0.455** | **+0.055 (p<0.001)** |
| 영어 (대조군, 손대지 않음) | 0.649 | 0.649 | +0.000 |

영어가 정확히 +0.000 인 것이 실험이 오염되지 않았다는 증거다.
**언어 격차가 0.193 에서 0.082 로 58% 줄었다.**

한국어 층별로는 easy +0.158(p=0.022), medium +0.140(p=0.006), hard +0.035(판정 불가).
**되살릴 전문 용어가 있는 층일수록 크게 돕는다.** 일상어로 묻는 hard 층에는 도움이 안 된다.

**학습을 한 번도 하지 않았고 프롬프트 한 줄이다.** 같은 날 잰 학습한 변환기(dpo)는
Recall +0.018(판정 불가)에 nDCG −0.016(나쁨)이었다. 방향이 문제였지 노력이 부족했던 것이
아니다 — 변환기는 arXiv 채널에만 작용했고, 번역은 성능의 거의 전부를 만드는 로컬 채널에
작용한다.

재정렬까지 영어로 해 봤으나 이득이 없었다(Recall +0.006 p=0.678, nDCG −0.007 p=0.226).
**재정렬은 원본 질문으로 유지한다** — 사용자 의도를 재는 단계이므로 사용자가 실제로 쓴 말을 쓴다.

### 난이도 축이 제대로 작동한다 (새 평가셋의 첫 증거)

| 난이도 | 누가 묻나 | Recall@10 | 후보 상한 |
|---|---|---|---|
| easy | 대학원생, 정확한 학술어 | **0.877** | 0.939 |
| medium | 학부 연구생 | 0.605 | 0.702 |
| hard | 1~2학년, 일상어 | **0.228** | 0.404 |

**쉬울수록 잘 맞히고 어려울수록 못 맞힌다.** 옛 평가셋은 이게 뒤집혀 있어서(hard 0.970,
이론적 상한 0.897 을 넘었다) 폐기해야 했다(#32). 새 평가셋은 설계대로 단조롭게 나온다 —
이 데이터로 잰 값을 믿어도 된다는 첫 증거다.

언어별로는 영어 0.637 대 한국어 0.503 이었다(번역 적용 전). 번역을 넣은 뒤에는 한국어가
0.567 로 올라 격차가 0.082 로 줄었다.

### 변환기도 arXiv 채널도 정당화되지 않았다 (ISSUE #37)

시험용에서 짝지은 검정 결과다.

| 비교 | Recall@10 | nDCG@10 |
|---|---|---|
| 변환기 있음 vs 없음 | +0.018 **(p=0.101, 판정 불가)** | −0.016 **(p=0.008, 나쁨)** |
| 두 채널 vs 로컬 단독 | +0.018 **(p=0.101, 판정 불가)** | −0.043 **(p<0.001, 나쁨)** |

개발용에서 겨우 유의미했던 Recall 이득(+0.026, p=0.046)이 **시험용에서 재현되지 않았다.**
반면 만족도 손해는 양쪽에서 모두 재현됐다.

**변환기는 로컬 채널에 영향을 주지 않는다** — 로컬 의미 검색은 원본 질문을 쓴다. 그래서
변환기를 아무리 잘 만들어도 arXiv 채널을 통해서만 작용하고, **그 채널이 후보 상한에 보태는
몫은 @100 에서 0.038 뿐이다**(로컬 단독 0.643 대 합집합 0.681). 이것이 지금 구조에서
변환기 개선의 **천장**이다.

> **그래도 arXiv 채널을 당장 버리지는 않는다.** 평가셋의 정답 논문이 전부 로컬 색인 안에
> 있어서, 이 평가는 "색인 밖 논문(어제 올라온 논문)을 못 찾는다"는 약점을 **구조적으로
> 잴 수 없다.** 남은 근거는 정확도가 아니라 **최신성과 범위**뿐이다.

### 옛 평가셋(v1) 숫자 — 인용할 때 반드시 출처를 밝힐 것

| 항목 | 값 |
|---|---|
| 옛 경로 (변환기 + arXiv + 재정렬) | 0.427 |
| 새 경로 (로컬 + 재정렬) | 0.680, **hard 누수를 뺀 정직한 값 0.535** |
| 두 채널의 추가 이득 | +0.003, p=0.889 (잡음) |

v1 은 hard 난이도 누수(#32)와 학습 소모(#25) 때문에 폐기했다. 위 값을 인용할 때는
**"옛 평가셋 기준"** 이라고 반드시 적는다. 새 평가셋 값과 직접 비교하면 안 된다.

### 지금 막고 있는 것 — 후보 확보가 아니라 순위다

실패한 96문항을 분해했다(옛 시험용 300문항).

| 구간 | 상태 | 문항 |
|---|---|---|
| A | 1차 검색이 30등 안에 넣었는데 놓침 | 9 |
| B | 31~300등에 있었는데 못 끌어올림 | 26 |
| C | 300등 밖이라 재정렬이 보지도 못함 | 28 |
| D | 두 채널 어디에도 없음 | 33 |

그리고 재정렬의 실제 회수 능력은 **깊이에 따라 절벽처럼 무너진다.**

| 정답의 1차 등수 | 1~10 | 11~30 | 31~100 | 101~200 | 201~300 |
|---|---|---|---|---|---|
| 재정렬이 10위 안에 살린 비율 | **0.956** | **0.938** | 0.684 | 0.350 | **0.125** |

**교차 인코더는 이미 위에 있는 정답만 지킨다. 깊은 곳에서 끌어올리지 못한다.**
그러므로 "후보를 더 깊이 가져오자"(깊이 1000)는 답이 아니다 — 기대 이득 +0.005~0.012 인데
재정렬 비용은 3.3배다. **고쳐야 할 곳은 1차 검색이 정답을 30등 안에 넣게 만드는 것이다.**

### 가장 큰 구멍 — 잰 성능과 실제 제품이 달랐다 (2026-08-13 해소)

논문 71만 편 로컬 색인이 `app.py` 에 한 줄도 연결돼 있지 않았고, 앱은 학습해 둔 변환기(dpo)가
아니라 계층 변환기를 쓰고 있었다(평가 0.680 대 서비스 0.427). **2026-08-13 에 앱을 새 구조로
옮겼고, 2026-08-14 에 평가 하네스도 서비스와 같은 조건으로 맞췄다**(로컬 채널에 원본 질문을
넣는 `--local-query raw` 가 기본값).

### 응답 시간 — 기준을 넘는다 (2026-08-14 실측)

| 단계 | 첫 질문 | 워밍업 후 |
|---|---|---|
| 논문 지목 확인 | 4.1초 | 0.4초 |
| 쿼리 변환 | 20.0초 | 3.5초 |
| 로컬 의미 검색 | 14.6초 | 0.2초 |
| arXiv 검색 | 1.5초 | 1.2초 |
| 재정렬 | 6.8초 | 1.3초 |
| **추천 이유 생성** | 26.1초 | **14.6초** |
| **합계** | **73.0초** | **21.1초** |

기준은 "사람은 30초를 넘으면 떠난다"인데 **첫 질문이 73초**다. 가장 큰 단계는 추천 이유
생성(14.6초)이고, 그다음이 쿼리 변환(3.5초) + arXiv 검색(1.2초) + 논문 지목 확인(0.4초)
= **arXiv 채널에 딸린 5.1초**다. ISSUE #37 대로 arXiv 채널을 옵션으로 내리면 워밍업 후
21.1초에서 약 15.8초가 되고 만족도는 오른다.

### ① 쿼리 변환 모듈 — `src/rewriter/`

파일 4개: `base.py`(규약 + build_rewriter + Ollama 호출) · `baselines.py`(계층/한번에/HyDE +
프롬프트) · `finetuned.py`(학습한 dpo 모델) · `paper_resolver.py`(특정 논문 지목 처리)

- ✅ 언어 모델 선정 — **Qwen3-4B** (한국어 이해 + 영어 전문 용어 생성 + 자유 라이선스)
- ✅ 계층 변환 (의도→개념→학술용어→검색어). JSON 스키마 강제로 파싱 실패 원천 차단(#1, #3)
- ✅ 기준선 변환기 — `passthrough`(변환 안 함), `single_step`, `hyde`
- ✅ **검색 보상 학습(SFT + DPO)** — 후보 검색어를 실제 arXiv 검색으로 채점해 라벨 확보.
      옛 시험용 300문항에서 기준선의 2.05배 (0.167 → 0.343, p<0.001)
- ✅ **변환의 가치는 전적으로 한국어에서 나온다** — 한국어 0.013 → 0.333(25배).
      원본 한국어를 arXiv 에 그대로 넣으면 88.2% 가 결과 0건. 영어는 어떤 변환기도
      기준선(0.327)을 유의미하게 넘지 못했다
- ❌ ~~정답 논문에서 라벨 뽑아 재학습~~ — 실패(#17). 처음 보는 논문의 고유 용어는 유추 불가
- ❌ ~~어휘 조회 + 상용구 필터~~ — 무효(#22). 정답 논문 초록을 베끼는 편향이었다
- ❌ ~~검색어 용어 손질(term_repair)~~ — 폐기(#33). 모든 K 에서 성능이 떨어졌고
      실시간 서비스에서 쓸 수도 없다
- ✅ **한국어를 영어로 옮기는 변환기(`translate`, 2026-08-14)** — 시험용에서 한국어
      Recall@10 +0.111(p=0.001), nDCG +0.055(p<0.001). 학습 0회, 프롬프트 한 줄.
      영어 질문은 건너뛰므로 대조군이 정확히 +0.000 이다. 서비스에 연결 완료
- ⚪ 학습한 변환기(dpo) — 새 평가셋에서 기여가 판정 불가(#37). arXiv 채널 전용으로 남겨 둠
- ⬜ hard 층(일상어)을 도울 방법 — 번역이 안 통하는 유일한 층이다(+0.035, 판정 불가)

### ② 검색 모듈 — `src/retrieval/`

파일 4개: `corpus.py`(코퍼스 적재 + 논문 번호 정규화) · `local_index.py`(71만 편 색인) ·
`arxiv_live.py`(실시간 검색) · `ranking.py`(RRF 융합 + 교차 인코더 재정렬)

- ✅ **실시간 arXiv 검색** — 3초 간격·단일 연결(정책 준수), 429/503 지수 백오프(#12), 디스크 캐싱
- ✅ **논문 71만 편 코퍼스** — Kaggle 스냅샷에서 cs·stat.ML·eess 계열 + 2021년 이후 **전부**
      추출(716,183편, 1.03GB). 표본이 아니라 모집단이라 표본 추출 왜곡이 없다
- ✅ **메모리를 적게 쓰는 큰 색인** — 시스템 메모리가 15GB 뿐이라 세 가지를 다르게 만들었다:
      ⓐ 본문은 파일 위치만 기록하고 필요할 때 꺼내 읽는다 ⓑ FAISS 를 안 쓴다(벡터 복사본이
      한 벌 더 필요해진다) ⓒ 임베딩을 조각으로 나눠 계산하고 바로 디스크에 쓴다(이어하기)
- ✅ **임베딩 71만 편 계산 완료** — 초당 73편, 163.5분, 2.93GB
- ✅ **순위 합치기(RRF)** — 점수를 그대로 더하면 **어느 채널이 옳은가가 아니라 점수 눈금이
      큰 쪽이 이긴다.** 그래서 점수 대신 순위를 쓴다
- ✅ **논문 번호 표기 통일** — `split("v")[0]` 이 옛 형식 번호를 자르던 문제(#27) 해결.
      이걸 놓치면 두 채널이 함께 찾아낸 논문일수록 점수가 반으로 쪼개진다
- ✅ **색인·코퍼스 짝 확인** — 짝이 안 맞으면 오류 없이 엉뚱한 논문 본문을 읽는다(#28).
      크기 지문 + 표본 대조로 막고, 단위 테스트로 못박았다
- ✅ **교차 인코더 재정렬** — `BAAI/bge-reranker-v2-m3`(568M, 다국어). 후보를 **원본 질문**과의
      관련도로 재정렬. 옛 경로에서 0.343 → 0.427 (p<0.001)
- ❌ ~~작은 코퍼스(3만 편) 검색기 일체~~ — 71만 편 색인이 대체. BM25·hybrid·dense 삭제
- ✅ 두 채널이 이득인지 시험용에서 판정(#37) — Recall 판정 불가, 만족도는 나빠짐

### ③ 성능 평가 모듈 — `evaluation/`

파일 4개: `dataset.py`(평가셋 제작 + 누수 감사) · `pipeline_eval.py`(파이프라인 실행 + 응답

## 5. 서비스 관점 경고

### ① 검색 속도

| 단계 | 측정값 |
|---|---|
| 로컬 의미 검색 (깊이 100) | 질문당 약 **0.17초** |
| 로컬 의미 검색 (깊이 1000) | 질문당 약 0.22초 |
| 교차 인코더 재정렬 | **후보 수에 비례해 늘어난다** |
| 추천 이유 생성 | 모델이 GPU 에 있으면 10.5초, CPU 로 밀리면 **229.6초** |

재정렬과 추천이 위험 요소다. 깊이 100 일 때 재정렬 대상은 23,748편, 깊이 300 으로 늘리면
64,562편(2.7배)이다. 게다가 **GPU 한 장이라 사용자가 여러 명이면 줄을 선다.**

### ② arXiv 정책 위반 상태 (공개 전 필수)

- **arXiv 메타데이터 출처 표기(CC0) 가 화면에 없다.**
- **"이 서비스는 arXiv 의 후원이나 보증을 받지 않았다"는 문구가 없다.** arXiv 이용 약관은
  "arXiv 가 지원하거나 보증하는 것처럼 표현하지 말 것"을 **명시적으로 금지**한다.
- 로컬에 저장한 것은 제목·초록·논문 번호 같은 **메타데이터뿐이라 저장 자체는 허용된다**(CC0).
  다만 논문 원문을 우리 서버에서 제공하면 안 된다. 사용자는 arXiv 초록 페이지로 보내야 한다.
- 둘 다 조치에 몇 시간이면 되는데 **안 하면 서비스를 내릴 수 없다.**

### ③ 새 구조가 만든 새로운 위험 — "못 찾았다"고 말할 수 없게 된다

기존 arXiv 키워드 검색은 못 찾으면 **결과 0건**을 돌려줬다. 그런데 로컬 의미 검색은
**항상 상위 10편을 채워서 돌려준다.** 아무리 관련 없는 질문이어도 유사도가 가장 높은 10편이
나온다. 이것을 그대로 화면에 뿌리면 **무관한 논문을 추천으로 포장하는 서비스**가 된다.

→ 최소 관련도 기준선을 정하고, 그 아래면 "찾지 못했다"고 정직하게 말해야 한다. **미착수.**

### ④ 배포에 필요한 자원이 커졌다

| 파일 | 크기 |
|---|---|
| 논문 71만 편 본문 | 1.03GB |
| 임베딩 | 2.93GB |
| 재정렬 모델 + 임베딩 모델 + 언어 모델 | 별도 |

시스템 메모리는 15GB, GPU 는 16GB 다. **지금 배포 설정은 3만 편 시절 기준이라 다시 짜야 한다.**

### ⑤ 시험용 평가셋이 마지막 남은 깨끗한 자료다

옛 평가셋은 시험용까지 설정 선택에 소모돼 폐기해야 했다(#25). 새 시험용
(`data/eval/test.jsonl`)을 보면서 설정을 이리저리 바꿔 맞추면 **똑같은 일이 반복된다.**
**시험용으로는 "확정" 판정만 하고, 개선 방향 탐색은 개발용에서 한다.**

  **정확히 descriptive metadata 뿐**이었다. 캐글 데이터셋도 CC0 임을 확인했다.
